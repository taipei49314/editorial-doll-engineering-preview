# ADR 0010: Make M2.2 generation immutable and target-aware

Status: accepted

## Context

M2.1 proves portable source identity and PNG structure. M2.2 introduces native
decoding, byte-producing image transforms, and a mutable `catalog.json` pointer.
Partial output, path attacks, or a false cross-platform byte guarantee would
make a generated catalog untrustworthy.

Production Muse appearance remains undecided, but decoded checks and synthetic
full-frame derivatives are objective and can proceed independently.

## Decision

- Pin Sharp exactly to `0.35.3` and commit the pnpm lockfile.
- Generate each runtime and thumbnail directly from the accepted master with a
  fixed full-frame transform and PNG encoder configuration.
- Require source standard-sRGB declaration; normalize outputs to pinned Sharp's
  canonical embedded sRGB profile, normalize inherited density by rewriting
  only `pHYs` to `(1000,1000,unit=1)` plus its CRC, avoid
  `withMetadata`/EXIF, and strip private metadata.
- Identify releases after generation using the canonical source report,
  transform-contract version, exact generator fingerprint, and ordered
  derivative release-relative path/hashes. Add the generated-root release path
  only after identity is known, avoiding a self-reference. Require repeatability
  on one host/configured native runtime rather than promising same-fingerprint
  or cross-platform PNG byte identity.
- Publish an immutable release directory first, then atomically replace the root
  generated-asset `catalog.json`. Never replace a release directory. Serialize
  source recheck, ledger rescan, promotion, and pointer replacement with one
  exclusively acquired publication lock.
- Apply ADR 0011's owner-controlled-directory precondition. The lock coordinates
  cooperating publishers; it is not presented as a sandbox against a malicious
  process running under the same OS account.
- Treat retained release catalogs as the local `id@version` immutability ledger.
- Include raw manifest and master hashes plus canonical asset/technical payload
  in each complete source fingerprint and revalidate it before publication.
- Keep visual-quality claims that pixels cannot prove as explicit QA evidence.

## Consequences

- Failure cannot expose a half-generated current catalog.
- Windows/Linux or different machines may have different release IDs when
  native output bytes differ, while both must satisfy identical decoded
  invariants.
- The generated asset catalog is not a Domain catalog and contains no fabricated
  Muse.
- M2.2 adds no deletion command; generated releases accumulate until a future
  separately authorized retention policy exists.
- Production matte, semantic crop, and split-seam approval still requires the
  future mini art pack.
